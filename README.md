# 아테나 PC 1.0

사업장의 재고·거래처·판매·입금·반품을 PC에 기록하는 첫 버전입니다.
인터넷 연결이나 서버 가입 없이 실행합니다. 화면은 기본 브라우저에 열리고,
기록은 브라우저 임시 저장소가 아닌 PC의 SQLite 데이터 파일에 남습니다.

## 처음 실행하기

1. ZIP 파일을 PC에 내려받아 **압축을 모두 풀어 주세요.** 압축 파일 안에서 바로 실행하지 마세요.
2. **아테나_실행.cmd**를 두 번 클릭하세요.
3. 기본 브라우저에 아테나가 열립니다. 실행 창은 업무 중 열어 두세요.

**필요 환경: Python 3.10 이상 + SQLite 모듈, 최신 Edge 또는 Chrome.**
일반적인 Windows용 Python 설치에는 SQLite 모듈이 포함되어 있습니다.
별도 pip 설치, Node.js, npm, 데이터베이스 서버는 필요하지 않습니다.
Python이 설치되어 있지 않으면 실행 파일이 안내를 표시합니다.
[Python 공식 Windows 다운로드](https://www.python.org/downloads/windows/)를 사용하세요.
Python 설치가 끝난 다음부터 아테나 사용에는 인터넷이 필요하지 않습니다.

설치형 EXE가 아니라 Python으로 실행하는 Windows용 프로그램 묶음입니다.
이 파일을 내려받는 것만으로 PC에 자동 설치되지는 않습니다.
기존 ATHENA 프로젝트 폴더를 덮어쓰지 않고 별도 폴더에서 실행하세요.

## 먼저 연습해 보기

**아테나_체험.cmd**를 실행하면 가상의 품목과 거래처, 판매 자료가 있는 체험 장부를 엽니다.
화면 상단에 체험 모드 표시가 나옵니다. 체험 자료는 실제 장부와 완전히 다른 폴더에 저장됩니다.
예시 가격·거래처·판매량은 실제 사업 자료나 D-TX의 가격 정책을 의미하지 않습니다.

실제 업무를 시작할 때에는 **아테나_실행.cmd**를 사용하세요. 처음에는 빈 장부가 열립니다.

## 첫 업무 순서

1. **설정 및 백업 → 사업장 정보**에서 상호와 전화, 주소를 입력합니다.
2. **재고 → 품목 등록**에서 품목명, 규격, 단위, 단가, 현재 보유한 시작 재고를 입력합니다.
3. **거래처 → 거래처 등록**에서 거래처를 등록합니다. 도입 전에 받을 돈이 있다면 기존 미수금과 기준일을 입력합니다.
4. **판매 등록**에서 거래처와 품목을 검색해 선택하고, 수량·단가·실제로 받은 금액을 입력합니다.
5. **판매 저장**을 누르면 재고가 차감되고 입금과 미수금이 함께 기록됩니다.

품목 코드와 거래처 이름을 검색 입력한 다음 목록의 항목을 선택하세요.
같은 품목은 한 줄에서 수량을 합칩니다. 수량과 원화 금액은 정수로 입력합니다.
한 품목의 단위는 일관되게 사용하세요. 박스와 낱개의 자동 환산은 없습니다.

| 거래처 관리 | 연락처·담당자·주소·메모, 도입 전 미수금, 거래 원장을 관리합니다. |

| 환불 | 반품으로 돌려줄 돈이 발생하면 정확한 금액을 표시합니다. 실제 환불 후 완료에 체크해야 저장됩니다. |
| 입금 정정 | 잘못 입력한 양수 입금은 판매 상세에서 전체 금액을 정정할 수 있습니다. 원본은 남기고 반대 기록을 추가합니다. |

| 삭제·휴지통 | 품목·거래처·판매·입금·반품·수동 입출고를 삭제하고 휴지통에서 복구합니다. 판매 전체 삭제는 연결된 재고·입금·반품을 함께 원상 복구합니다. |

## 금액과 수정 규칙

- 거래금액은 **입력한 최종 단가 × 수량**입니다. 부가세·할인율·세액을 자동 계산하지 않습니다.
- 명세서는 거래 내역 확인용이며 세금계산서가 아닙니다. 전자세금계산서 발행·세무신고 기능은 없습니다.
- 오늘·당월 순판매는 해당 날짜에 등록된 판매금액에서 그 날짜의 반품금액을 뺍니다.
- 순입금은 양수 입금에서 환불과 입금 정정을 뺀 금액입니다.
- 판매 목록은 판매일로 조회하며, 금액 열은 현재까지 반영된 반품·입금의 누적값입니다. 시작 미수금도 이 목록에 표시됩니다.
- 도입 전 미수금은 받을 금액에는 포함되지만 새 매출에는 포함되지 않습니다.
- 입금 날짜보다 나중인 거래에는 입금을 배정하지 않습니다. 초과 입금·선수금은 지원하지 않습니다.
- 재고 부족 판매, 중복 품목 행, 소수 수량, 초과 반품, 미수금 초과 입금은 저장되지 않습니다.
- 품목명·단가를 수정해도 과거 판매 당시 품목명·단가·거래처명은 유지됩니다.
- 잘못 입력한 판매는 상세 화면의 **거래 전체 삭제**로 휴지통에 보낼 수 있습니다. 연결된 출고·입금·반품·환불도 함께 취소되며 복구하면 다시 반영됩니다.
- 삭제나 복구 때문에 재고가 음수가 되거나 입금·미수금 계산이 깨지는 경우에는 안전을 위해 처리하지 않습니다.
- 판매·입금·반품·입출고 수정 후에도 재고와 미수금을 다시 검증하며, 계산이 깨지는 수정은 전체 취소됩니다.
- 반품이 연결된 판매의 품목·수량은 반품을 먼저 휴지통으로 옮긴 뒤 수정합니다. 반품 복구가 새 판매 내용과 충돌하면 복구되지 않습니다.
- 휴지통의 영구 삭제는 화면상 복구 가능성을 제거하지만 삭제·복구 작업 이력은 장부 안전을 위해 유지합니다.
- 이미 환불에 연결된 입금은 전체 정정이 제한될 수 있습니다. 장부의 입금액보다 더 큰 정정을 막습니다.
- 반품은 재판매 가능한 재고로 들어갑니다. 파손·불량품은 이어서 재고 조정에서 제외하고 사유를 남깁니다.
- 입출고 이력은 기록된 날짜를 표시합니다. 과거 특정일의 재고 평가나 소급 원가 계산은 제공하지 않습니다.

## 저장 위치와 백업

Windows 실제 장부: `%LOCALAPPDATA%\ATHENA-PC\athena.db`

Windows 체험 장부: `%LOCALAPPDATA%\ATHENA-PC-Demo\athena.db`

정확한 위치는 **설정 및 백업 → 저장 폴더**에 표시됩니다.
실행 프로그램 폴더와 장부 폴더가 나뉘어 있어 프로그램 업데이트 시 자료를 보존하기 쉽습니다.
브라우저 캐시를 지워도 DB 파일은 그대로 남습니다.

- 저장할 때마다 당일 자동 백업을 갱신하고 최근 **30개 날짜**를 보관합니다. 같은 날의 모든 변경 버전을 보관하는 방식은 아닙니다.
- **현재 장부 백업 내려받기**로 전체 자료를 .db 파일로 저장할 수 있습니다.
- PC 고장에 대비하려면 백업을 USB 등 다른 저장장치에도 보관하세요.
- 복원은 현재 자료를 백업 시점의 자료로 교체합니다. 복원 직전 현재 장부를 `before-restore-...db`로 별도 보존합니다.
- 복원 가능한 파일은 이 버전에서 만든 백업이며 최대 50MB입니다. 다른 DB나 연결이 손상된 백업은 거부합니다.
- 잘못 복원했으면 **설정 및 백업**에서 복원 전 장부를 내려받아 다시 복원할 수 있습니다.
- 백업은 암호화되지 않은 전체 장부입니다. PC 사용자 계정과 백업 보관 위치를 기준으로 접근을 관리하세요.
- 프로그램 실행 중에는 원본 `athena.db`를 직접 복사·교체하지 말고 화면의 백업·복원을 사용하세요.

## 종료와 재실행

실행 창에서 **Ctrl+C**를 누르면 종료합니다. 브라우저만 닫으면 프로그램은 계속 실행됩니다.
실행 파일을 다시 누르면 이미 실행 중인 장부 화면을 다시 엽니다.
재실행 시 내부 접속 주소가 바뀔 수 있으므로 주소를 즐겨찾기하기보다 실행 파일을 사용하세요.

## 현재 버전의 범위

이 버전은 **한 PC의 로컬 업무 장부**입니다. 4명의 가족이 같은 PC에서 사용할 수 있지만,
서로 다른 PC·스마트폰의 동시 접속이나 사용자별 권한·변경자 식별 기능은 없습니다.
외부 인터넷에서 접속할 수 있게 서버를 공개하지 마세요.

매입대금·매입처 정산, 원가·손익회계, 급여, 출고 예약·주문 대기,
카카오톡·Google Sheets·문자·이메일·AI 자동화, Excel 일괄 가져오기는 아직 포함되지 않았습니다.
기존 ATHENA 소스는 제공되지 않아 이 패키지에 병합하거나 기존 자료를 이관하지 않았습니다.

실제 거래를 옮기기 전, 체험 장부에서 사업장의 입력 흐름과 단가 기준을 먼저 확인하세요.
상세 검증 범위는 TEST_REPORT.md, 개발 구조는 DEVELOPMENT.md에 정리했습니다.

## 실행 문제 해결

- **Python을 찾지 못함:** Python 3.10 이상을 설치한 뒤 다시 실행합니다. 터미널에서 `py -3 --version`으로 확인할 수 있습니다.
- **화면이 안 열림:** 실행 창의 오류 문구를 확인하고, 실행 파일을 한 번 더 누릅니다.
- **다른 화면에서 자료 변경 메시지:** 편집 창을 닫고 새로고침한 뒤 다시 입력합니다. 오래된 화면이 새 기록을 덮어쓰는 것을 막는 기능입니다.
- **저장 결과를 확인하지 못함:** 재입력하기 전에 새로고침하여 해당 거래가 이미 저장되었는지 확인합니다.
- **자동 백업 실패:** 저장 공간과 저장 폴더의 쓰기 권한을 확인하고 수동 백업을 내려받습니다.
- **오류 기록:** 설정에 표시된 장부 폴더의 `athena-error.log`에 기록됩니다.

## 개발자가 직접 실행하는 경우

```bash
python run.py
python run.py --demo
python -m unittest discover -s tests -v
```

검증용 임시 경로는 `--data-dir 경로`, 브라우저 자동 실행 생략은 `--no-browser`를 사용합니다.
`--demo --data-dir`을 함께 사용할 때는 실제 장부가 없는 별도 경로를 지정하세요.
